# Learnings

A dated, append-only log of what was discovered while working on this repo — the history and reasoning that neither of the other two mechanisms keeps. Standing rules and conventions belong in [CLAUDE.md](CLAUDE.md) (kept current there via the `doc-sync` skill); feedback about working style belongs in Claude's own cross-session memory. This file is for context that doesn't rise to either: a decision and why, a dead end, an open question, or domain knowledge about the tooling itself rather than the site.

Updated automatically at the end of each session; read automatically at the start of the next one.

## Open questions

- Trailing slashes are only ever generated (`astro.config.mjs`'s `trailingSlash: 'always'`), never enforced server-side — noted as a possible future addition when trailing-slash generation was first added (PR #9, 2026-06-17) but never revisited. Both `/route` and `/route/` currently resolve; no `netlify.toml` redirect exists for this.

- The `featured` boolean in the `work` content collection schema (`src/content.config.ts`) is dead: `WorkSection.astro` picks the wide/featured card purely by lowest `order` after sorting (`const [featured, ...rest] = entries`), never by reading the `featured` field. `WorkCard.astro` does destructure `entry.data.featured`, but only to pick a font-size class, not for slot selection. Today `storyblok-migration.mdx` has both `order: 1` and `featured: true`, so they coincide by convention, but nothing enforces it — a future reorder could silently promote a different card without `featured` following it. Surfaced by `self-review` during the issue #64 HTML-comment cleanup (the deleted `WorkSection.astro` comment naming "Storyblok migration" as the featured card was the only place partially documenting this coupling). Out of scope there; still undecided whether the fix is wiring `WorkSection.astro` to select by `featured: true` instead of order-position, or removing the field.

### 2026-08-10

- Fixed a batch of WCAG contrast failures from an accessibility audit, verified via headless-Chromium canvas pixel sampling (ground truth) rather than hand-rolled OKLCH math — an initial hand-rolled conversion turned out imprecise enough to cast doubt on itself when cross-checked against a hardcoded hex in `og-image.ts`. Two systemic root causes: opacity modifiers (`text-muted/70`, `placeholder:text-muted/50`) silently re-blend an already-AA-validated token toward the backdrop without re-validation (3.51:1 vs. 7.33:1 at full opacity); and `text-accent` on the site's shared `bg-accent/10`-`/40` tint vocabulary (`InitialsAvatar`, `ThemeToggle`'s active pill, `InterlinkCard`'s hover state) compounds with `--color-accent`'s already-thin light-mode margin, dropping to 4.18-4.49:1 at typical tint alphas.
- Fixed the accent-tint failures by darkening the shared `--color-accent` token (52%→49% L, light mode only) rather than patching each component's tint value separately, after the user pushed back on the per-component proposal — patching only 2-3 of the documented shared-vocabulary components would have fragmented it into inconsistent scales, while the token fix resolves every current and future consumer at once. Also fixed the Leadership category badge (`yellow-700`→`yellow-800`; 4.01:1 against its actual `bg-card` rendering context) and added a site-wide skip-to-main-content link. `self-review` caught that the skip link's `id="main-content"` targets initially lacked `tabindex="-1"` — without it, activating the link scrolls the viewport but leaves DOM focus on `<body>`, since `<main>` isn't natively focusable.
- The skip link's `id="main-content"`/`tabindex="-1"` pair was first added inline to all 8 pages' `<main>` tags, then extracted into `src/components/layout/Main.astro` after the user flagged the duplication directly (not via `self-review`) — a case where the abstraction was worth it despite CLAUDE.md's default bias against premature abstraction, since forgetting the pair on a future page silently breaks the skip link rather than erroring. Left the skip link's own visible text ("Skip to main content") hardcoded inline in `BaseLayout.astro` rather than moving it to `src/data/`, matching how other single-use a11y strings in the codebase already work (`Header.astro`'s `aria-label="Toggle navigation"`, `ThemeToggle.tsx`'s per-icon `label`s) — `src/data/*.ts` is reserved for content that repeats as structured lists or that a non-developer might edit (nav destinations, bio copy, recommendations), not one-off UI microcopy.

### 2026-07-01

- Adding a second animated element (a ping ring) to a pulsing dot creates visual beat interference that reads as a "double breathe" regardless of how the two durations are synchronized — the ring's scale+opacity expansion is a distinct visual event that competes with the inner dot's opacity breathe. The fix was to drop the ring and use a single dot with a symmetric `ease-in-out` opacity cycle; the ping ring idea is a dead end for this "constant breathe" use case.
- Tailwind v4 auto-generates an unconditional `.animate-*` utility class from every `--animate-*` token in `@theme`, which silently overrides any `@media (prefers-reduced-motion: no-preference)`-gated manual class definition on the same element — the motion guard only holds if the keyframe is also undefined outside the media block (undefined keyframe = animation none). Promoted to [CLAUDE.md](CLAUDE.md) under the Tailwind v4 stack-facts bullet.
- An infinite CSS animation whose first keyframe is below the element's natural property value needs `animation-fill-mode: backwards` (or `both`) — without it, the browser renders one frame at the natural value before snapping to the keyframe value when the first tick fires. Caught by `self-review` on this session's `dot-breathe` keyframe (`opacity: 0.3` at 0% vs. the span's default `opacity: 1`).
- Running `npx prettier --check` directly against a standalone `.sources.txt` file (e.g. `storyblok-migration.sources.txt`) errors with "No parser could be inferred" (exit 2), which looks like a real formatting failure — but the project-wide `npm run format:check` (`prettier --check .`, glob-based) silently skips the same file with no error. The `.txt` extension has no registered Prettier parser either way; the difference is glob mode tolerating unparseable files where direct-path mode doesn't. Not a bug to fix — just don't `prettier --check` a `.sources.txt` file directly to sanity-check it.

### 2026-06-25

- Creating a brand-new top-level `.claude/skills/` directory mid-session isn't picked up by Claude Code's live file watcher — it only watches directories that already existed when the session started. A restart (or fresh session) is required before any skill in a newly-created directory becomes invocable. Editing skills inside an already-watched directory does take effect live.
- A skill invoked with `context: fork` (e.g. `self-review`) only loops back to the orchestrator when Claude invokes it mid-task and stays in the same turn. If a human runs it directly as a standalone `/self-review`, the findings return as plain output with nothing to act on them automatically — see CLAUDE.md's `self-review` section for the fix-it-yourself follow-up this requires.
- Deleted `feedback_american_english.md` and `feedback_commit_scope.md` from local memory — both were already fully duplicated in committed files (CLAUDE.md's "American English spelling" bullet, and `conventional-commits/SKILL.md`'s "Scope" section). Repo-specific corrections should get promoted to a portable, committed file instead of resting in local-only memory; `doc-sync`'s table now has an explicit row for this.
- When evaluating whether a recurring task is worth a dedicated skill, check git history for repeat incidents rather than going on plausibility alone. - Root-caused the "dark mode persists across client-side navigation" `navigation.spec.ts` failure (previously an open question): Astro 7's `astro dev` auto-detects agentic CLI environments via the `am-i-vibing` package (it checks for `CLAUDECODE`, among others) and silently daemonizes itself in the background instead of blocking in the foreground. When Playwright's `webServer` spawns `npm run dev:astro` under Claude Code, the spawned process inherits that env var, exits immediately after forking the real daemon, and Playwright loses the ability to tear that daemon down — it survives past the test run. A later `npm run build` (run via the documented build-then-test order) then overwrites the shared Vite dep-optimizer cache (`node_modules/.vite/deps`) the orphaned daemon serves from, including `react/jsx-dev-runtime`, whose production build strips the `jsxDEV` export entirely. Every `client:load` React island (`ThemeToggle`, `ContactForm`) then throws `_jsxDEV is not a function` on hydration and never mounts — fully deterministic given that on-disk state, not flaky. Fixed in `playwright.config.ts` by setting `env: { ASTRO_DEV_BACKGROUND: '1' }` on the `webServer` config, which opts back into normal foreground behavior (the name is misleading — setting it disables the auto-background, it doesn't enable it) so Playwright always owns a fresh, correctly-torn-down server. Confirmed fixed across two full build-then-test cycles with no orphaned daemon left behind either time. This is local-environment-only (CI never sets `CLAUDECODE` and runs build/test in isolated jobs), so it never showed up as a real CI failure — the PR #40 "CI failure" was likely something unrelated.
